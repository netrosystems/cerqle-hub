# Decision records

Create a decision record when work establishes or changes a durable product, architecture, security, data, provider, or operational rule.

Use `YYYY-MM-DD-short-title.md` and include:

- Date.
- Status: Proposed, Accepted, Superseded, or Rejected.
- Context: the problem and constraints.
- Decision: the behavior that future work must preserve.
- Consequences: tradeoffs, follow-ups and limitations.

Do not rewrite an accepted record to hide history. Add a newer record, mark the older one Superseded, and link the two. Current operational facts belong in `PROJECT_STATUS.md`, not in a decision record.
